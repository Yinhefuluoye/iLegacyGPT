# v1.2.0

## Added

- arm64 slice. The IPA is a fat binary containing armv7 and arm64, covering 32-bit devices and 64-bit devices that run iOS 9 or 10.
- iOS 9.3 deployment target.
- Build-time verification that the UI bundle parses as ES5.

## Changed

- The UI is compiled to ES5. `web/build.mjs` runs `tsc` with `web/tsconfig.es5.json` before bundling, because esbuild cannot lower to ES5.
- Deployment target and `MinimumOSVersion` are 9.3.
- The armv7 linker flag `-lgcc_s.1` is applied per architecture, since the SDK stub carries only armv7 and armv7s slices.

## Fixed

None.

## Known issues

- armv7 on iOS 9.3.5 / 9.3.6 (iPad 2, iPad 3, iPhone 4S, iPod touch 5) is not verified on hardware;
- arm64 on iOS 9 / 10 (iPhone 5s through iPhone 7) is not verified on hardware;
- flexbox and software-keyboard behaviour on Safari 9 are unverified;
- the follow-up request after a search tool call carries the retrieved documents as context; the `tool_calls` messages are not replayed.

# v1.2.0

## 新增

- arm64 切片。IPA 为包含 armv7 与 arm64 的胖二进制，覆盖 32 位设备与运行 iOS 9 / 10 的 64 位设备。
- 部署目标降至 iOS 9.3。
- 构建阶段校验界面产物可按 ES5 解析。

## 变更

- 界面产物改为 ES5。`web/build.mjs` 先以 `web/tsconfig.es5.json` 运行 `tsc`，再交由 esbuild 打包，因为 esbuild 无法降至 ES5。
- 部署目标与 `MinimumOSVersion` 均为 9.3。
- armv7 的链接参数 `-lgcc_s.1` 改为按架构下发，因为 SDK 中该 stub 仅含 armv7 与 armv7s 切片。

## 修复

无。

## 已知问题

- armv7 + iOS 9.3.5 / 9.3.6（iPad 2、iPad 3、iPhone 4S、iPod touch 5）未经真机验证；
- arm64 + iOS 9 / 10（iPhone 5s 至 iPhone 7）未经真机验证；
- Safari 9 上的 flexbox 与软键盘行为未验证；
- 检索工具调用后的续接请求以上下文形式携带检索结果，不重放 `tool_calls` 消息。
